# Living The Charge — application repository

This directory is the owner-requested standalone Git/build/deployment root. The surrounding workspace retains the legacy system and organizational references; never delete them. The latest packaging request supersedes the earlier requirement to keep the active applications directly at the surrounding workspace root.

- Flag new files, dependencies and changes outside the requested scope before building. Do not add libraries without owner approval or refactor unrelated code.
- Preserve routes, request/response formats, validation, permissions, provider behavior and existing functionality. Keep Supabase Auth/PostgreSQL/Storage, Stripe and Resend.
- **Never execute migrations/schema changes automatically on any database.** Present exact SQL, SHA-256, exact TEST/PRODUCTION target, effects/risks/verification/recovery, obtain explicit approval and wait. Credentials, task approval and TEST approval do not authorize production migrations. No startup/test/CI/worker/Docker/CDK path may migrate.
- Only use the owner's confirmed TEST database for integration testing. Local `.env` may contain live credentials; do not assume TEST. Never reset/truncate/seed/write to live. Use mocked tests while waiting. Secrets stay local/server-side, never committed or requested in chat.
- Do not deploy, create AWS resources, run live payments, send production newsletters, push or merge unless separately authorized. CI checks do not deploy or migrate.
- `frontend/` contains the existing public website and admin portal; `backend/` contains the Node API/worker; `infra/` contains IaC/Docker/runbooks. `admin/` contains documents only. Do not create future admin/portal modules unless separately authorized.
- Public content/design must remain unchanged: text, photographs, crops, typography, colours, layouts, routes, forms and interactions. Capture a baseline before presentation changes.
- Admin design follows the owner's latest direction: Geist Sans, compact navigation/summary strips, semantic status tokens, graphite dark mode, 8px cards/6px controls, 3:1 editor/support layouts, short headings and restrained weights. Public typography/radii remain their existing design. Use existing admin tokens and Lucide icons; keep optional help in info controls/disclosures.
- For UI work, inspect shared styles, admin tokens, Tailwind configuration, components, motion and tests before editing. Follow the available installed UI skills and workspace UI workflow when accessible; do not install skill dependencies without approval. Preserve responsive/focus/keyboard/reduced-motion/loading/empty/error/disabled states and unsaved edits.
- Use `rg` for searches. Run meaningful tests/builds/lint/type checks appropriate to changes. Report failures and unverified gates honestly; never weaken tests or delete the legacy reference to claim completion.
